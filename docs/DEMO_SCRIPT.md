# 90-second demo recording guide

Record the real local app after installing the selected Gemma model. A static sample walkthrough alone should not be presented as proof of live AI.

0–10s — “I built ScopeLedger for freelancers who keep hearing ‘can you add one more thing?’ It compares the ask to the agreement and helps draft a clear change order.”

10–25s — Show the two sources. Paste a scope with a marketing site, two visual revisions, excluded booking and an English-only launch. Paste requests for booking, a color revision, Spanish and a vague “more premium” request.

25–45s — Click Review with local Gemma. State the actual model and hardware. Explain that client text is processed by the local model. If speeding up a slow segment, label the edit and report the real elapsed time. Show actual results, including any mistake.

45–60s — Inspect a citation. Explain that source lines come from the documents while the classification is a suggestion. Override a wrong or ambiguous classification if needed. Point out that IDs prove a source exists, not that the model understood it.

60–75s — Enter your own estimates: illustratively, three hours for booking and two for Spanish at $100/hour. Select those changes. The $500 is a proposed quote, not measured savings or revenue.

75–85s — Export the owner-reviewed draft. Show that included and unselected items are absent. Client acceptance is pending; nothing has been sent.

85–90s — “Open weights let me run the comparison without sending client documents to a hosted AI provider. Next I’m testing this with freelance developers.” Show the public code URL and the real evaluation results.

Do not invent a first customer, payment, accuracy percentage, latency or user testimonial. Only claim those after collecting evidence.
